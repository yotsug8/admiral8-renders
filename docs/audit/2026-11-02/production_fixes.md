## Совместимость и повторение

Прежние команды и позиционные аргументы остаются:

```powershell
py -3.11 tools/skit/study.py examples --out study_result
py -3.11 tools/skit/grade.py input.mp4 output.mp4
py -3.11 tools/skit/grade.py target
py -3.11 tools/skit/mix.py input.mp4 output.mp4 scene.json
py -3.11 tools/skit/assemble_study.py recipe.json --assets assets_root --out delivery
```

Mix/grade теперь требуют `ffprobe` в PATH либо путь в `FFPROBE`.
Это уже используемый проектом инструмент (`finish_chase.py`); новый пакет
не устанавливался. За основу проверки кадров взят существующий подход
finish_chase: rational FPS + фактические timestamps. Его код не изменён.
FFmpeg выбирается, как прежде, через imageio_ffmpeg.

Старый JSON рецепта без новых полей по-прежнему работает. Каждая сборка
добавляет в выходную папку:

- `look_snapshot.json` — target, преобразователь и контрольные хеши;
- `recipe_frozen.json` — прежние пути к PNG/WAV относительно того же
  `--assets`, плюс встроенный snapshot;
- в `assembly_report.json` — `look_snapshot`, `look_snapshot_sha256`
  и, если target был задан файлом, `look_target_file_sha256`.

Повторить **закреплённый** вид: передать `delivery/recipe_frozen.json`
вместо исходного рецепта, прежний `--assets` и новую папку `--out`.
Повтор исходного незакреплённого рецепта намеренно может использовать
новый локальный target; сохранённый frozen-рецепт от него независим.

Дополнительные необязательные поля рецепта:

```json
{
  "look_profile": "legacy",
  "look_target": "grade_target.json",
  "look_target_sha256": "SHA256 байтов указанного файла"
}
```

Либо `look_snapshot`: объект сохранённого snapshot или путь к JSON внутри
`--assets`. Target и snapshot одновременно запрещены. Daylight отвергает
явный target. Hash файла target относится к исходным байтам; hash target
внутри snapshot и хеши состояния — к JSON с сортировкой ключей, без
пробелов, `allow_nan=False`. Это разные явно обозначенные проверки.
Существующий `--validate-only` проверяет явно переданный target/snapshot,
но не создаёт default target и не выполняет сборку/синтез.

## Границы

- Поддержан CFR с нулевым стартом и чётными размерами для yuv420p.
  VFR и ненулевой старт отклоняются до обработки вместо неявного изменения
  времени. Допуск timestamps — один тик контейнера плюс 1 мкс; это не
  поддержка произвольной VFR. Для проверки probe читает все timestamp-кадры,
  поэтому это дополнительный CPU/I/O-проход, не бесплатные metadata.
- Сохранность MP4 обеспечена при обычных ошибках; аварийное завершение ОС
  может оставить временную папку. Не добавлена блокировка одновременной
  записи в один выход. Исходные файлы предполагаются стабильными на время
  запуска; проверка количества кадров не заменяет блокировку входа.
- При аудиокопировании grade ограничивает длинный хвост по видео,
  короткую исходную дорожку не дополняет. AAC-границы зависят от пакетов;
  тестируетcя допуск, а не побитовое совпадение с PCM.
- Mix всё ещё использует прежний контракт scene/voices и общие промежуточные
  WAV внутри папки сценки; параллельное сведение в одну папку не заявлено.
  Исчезнувший SFX по-прежнему предупреждение. Полная перестройка микшера,
  субтитров, LUFS и остальных ветвей не входила в задачу.
- `_fish` временно меняет модульный FISH_KEY с finally; одновременные
  поточные вызовы с разными ключами не поддержаны. Исправлен путь передачи,
  доступность реального Fish/реестра не проверена. Полнота/целостность
  существующего голосового кэша отдельно не переаудирована.
- Snapshot строго требует прежние SHA256 grade/chase_look и NumPy;
  при смене реализации нужен осознанный новый snapshot, а не тихий replay.
  Хеши — контроль воспроизводимости, не подпись недоверенного JSON.
  Исходные PNG/WAV остаются внешними ресурсами; весь рецепт не становится
  автономным архивом. Межплатформенная побитовая идентичность Pillow,
  кодеков и произвольных аппаратных конфигураций не заявляется.
- Нет прослушивания, художественной оценки, реальных героев, полного
  production-рендера или утверждения о закрытии остальных находок аудита.
