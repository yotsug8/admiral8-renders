# Аудит production

Дата: 2026-11-01. Область: только 41 файл из `production_manifest.json`.

**Покрытие полное по чтению: 41/41 файлов, 8133/8133 строк manifest.** Все текстовые файлы фактически прочитаны целиком. Включая все 2328 строк таблицы деревьев; дополнительно структурно проверены все её 2306 записей. Статический аудит не подтверждает работоспособность движка, качество анимаций или звука и не является визуальным анализом каждого дерева.

Прочитаны AGENTS.md, глобальная инструкция RTK и PROJECT_STATE.md. Код, документы проекта, игровые настройки не менялись; `tools/check.py`, Blender, Dota, GPU, синтез речи и рендер не запускались. Созданы только этот отчёт и `production_coverage.json`. Наличие исходных изменений рабочей копии не приписывается аудиту. Дополнительные точечные чтения вне manifest использованы только для проверки связей и явно не входят в покрытие.

## Три главных вывода

1. Обычная повторная сборка `skit.py --all` может использовать кадры предыдущей версии сцены. Возобновление рендера не привязано к хешам сцены; необходимо различать продолжение того же рендера и новую версию.
2. Запись из движка не обеспечивает обещанное восстановление всех изменяемых настроек: туман и дальность остаются изменёнными, некоторые значения заменяются предполагаемыми стандартными.
3. Инструментов существенно больше, чем простой текстовый генератор сценок: есть перенос анимаций в DMX, сценическая площадка с обратной проекцией, операторские планы, каталог игровых реплик, сведение по явным контактам и воспроизводимая CPU-сборка. Однако общий `check.py` не проверяет весь этот набор, а его успех возможен при пропусках.

## Подтверждённые ошибки

Приоритеты ниже относятся к потенциальному влиянию на производство. Доказательства статические; отдельные сценарии воспроизведения не запускались.

### P1 — повторный рендер может сохранить старую картинку

`tools/skit/skit.py:699` выбирает папку только по имени сценки; `tools/skit/skit.py:666` повторно использует каталог кадров. Вызываемый рендерер по умолчанию не перезаписывает существующие кадры: `tools/blender/render_scene.py:930`, `tools/blender/render_scene.py:932`; это подтверждено точечным чтением строк 910–942 вне manifest. Связи с хешем нового scene.json, текста или параметров нет. При повторном `--all` после правки сценария старые PNG могут остаться, а новое сведение уже использует новые голоса/тайминг. Дополнительно `tools/skit/skit.py:733` читает всю непрерывную последовательность без ограничения `-frames:v`; при сокращении сцены старый хвост попадёт в raw MP4. `-shortest` в `tools/skit/mix.py:133` не исправляет старую картинку внутри новой длительности. Нужен отдельный каталог версии или проверяемый fingerprint возобновляемой сборки; исправления не выполнялись.

### P1 — неполное восстановление настроек игры

`tools/dota_engine/record.sh:31` меняет `fog_override_enable`, `fog_enable`, `r_farz`, но обработчик EXIT в `tools/dota_engine/record.sh:29` их не возвращает. `host_framerate` возвращается в 0 без чтения исходного значения. `r_depth_of_field` при неудаче чтения заменяется на 1 (`tools/dota_engine/record.sh:26`); тот же fallback есть в `tools/dota_engine/shots.sh:14`. Это противоречит обещанию возврата исходных настроек в комментариях скрипта и AGENTS.md. Нужны снимок всех затронутых значений и отказ до изменения при неполном снимке.

### P2 — --out в study.py не работает как заявлено

`tools/skit/study.py:3` документирует `--out <папка>`. `tools/skit/study.py:72` удаляет только аргументы, начинающиеся с `--`; значение папки остаётся входным файлом/каталогом. Выход всегда жёстко задаётся строкой 73. При указанной существующей папке её MP4 дополнительно анализируются, при несуществующей путь поступает декодеру как вход. Нужен разбор пары option/value.

### P2 — изменение скорости входного видео при fps != 30

`tools/skit/grade.py:108` декодирует исходные кадры, но `tools/skit/grade.py:109` передаёт их кодеру с фиксированными 30 fps, одновременно копируя исходное аудио. Аналогично `tools/skit/mix.py:131` получает метаданные, но строка 132 задаёт 30, а субтитры считают время `k/30` в строке 144. Например, 150 кадров пятисекундного источника 30 fps корректны, но 150 кадров десятисекундного источника 15 fps превращаются в пять секунд. Обычный skit-поток сам создаёт 30 fps; ошибка проявляется при самостоятельном вызове утилит с другим fps. Нужно сохранять временную шкалу либо явно отвергать неподдерживаемый источник.

### P2 — фильтр выбранных анимаций экспорта не применяется

`tools/dota_export.py:76` перебирает `*.vmdl_c`, а `tools/dota_export.py:81` сравнивает `f.stem` с именем героя. Для `kunkka.vmdl_c` stem равен `kunkka.vmdl`, не `kunkka`; условие не выполняется. Следовательно, переданный список анимаций не добавляется к CLI в штатном формате файлов, вопреки строкам 8 и 82. Это лишний экспорт и увеличение результата, не свидетельство потери всех анимаций.

### P2 — поздние анимации цели крюка удаляются

`tools/skit/skit.py:546` и `tools/skit/skit.py:549` сначала формируют анимации всех реплик, включая будущие. Затем `tools/skit/skit.py:554` для цели крюка оставляет только анимации раньше попадания и добавляет flail/stun. Все будущие разговорные анимации цели удаляются; запись voices и faces сохраняется (`tools/skit/skit.py:631`). Условие: после крюка должна заговорить его цель. Текущий `skits/kryuk.txt:17` содержит реплику бросавшего и не доказывает проявление этой ошибки в данном ролике. Дополнительно движение жертвы возвращается из первого уже случившегося крюка (`tools/skit/skit.py:498`–502), поэтому второй крюк той же цели не отрабатывается этой веткой.

### P2 — проверка расстояния героев смешивает абсолютную и относительную высоту

В `tools/dota_engine/stage.py:160` расстояние берётся по `pos[:3]`. При `ground` координата z здесь относительна земле; для проекции земля явно прибавляется в `tools/dota_engine/stage.py:138`, для Blender — в строке 293. Поэтому «касание» на склоне/разных уровнях может быть как ложным, так и пропущенным. Например, при разнице земли 200 и одинаковом локальном z высотная разница полностью исчезает из расстояния. Это проверка корней, не пересечения сеток даже после исправления высоты.

### P2 — совпавшие якоря не разводятся решателем

`tools/dota_engine/stage.py:191`–196: при dx=dy=0 выражение `hypot(...) or 1.0` делает L равным 1; защитная ветка `L < 1e-6` не выполняется. Обе поправки остаются нулевыми, и совпавшие подвижные якоря не расходятся. Нужен выбор направления именно для нулевого исходного расстояния. Это не относится к жёстким world-якорям, которые намеренно не двигаются.

### P2 — чтение повреждённого VPK/DMX может не завершаться

`tools/vpk_tool.py:23` завершает строку только на NUL: EOF даёт пустые bytes и бесконечный цикл. Такой же цикл в `tools/dota_engine/datamodel.py:91`–97. Условие — обрезанная строка файла без завершающего нуля. Нужна явная ошибка EOF. Повреждённые игровые архивы не создавались и не подавались утилитам.

### P2 — бинарный DMX не сохраняет тип беззнаковых чисел

`tools/dota_engine/datamodel.py:1016`–1017 возвращает обычные int вместо UInt8/UInt64; `tools/dota_engine/datamodel.py:697` выбирает тип записи по Python type. После read/write тип меняется, большие UInt64 затем не помещаются в signed int в строке 661. Для массивов UInt8/UInt64 lookup в строке 462 строит имена отсутствующих классов; перечень массивов в строке 431 сводит их к `_IntArray`. Ограничение общего DMX roundtrip доказано кодом; наличие этих атрибутов в используемом idle DMX не установлено. Основные каналы position/orientation этим выводом не объявляются сломанными.

### P2 — кеш голоса не обновляет изменившиеся субтитры

`tools/skit/voices.py:147`–155 строит ключ по произносимому тексту и при совпадении делает continue. Отображаемый текст обновляется только в строке 178. При замене `{старое|одинаковая озвучка}` на `{новое|одинаковая озвучка}` WAV правильно переиспользуется, но поле text в voices.json остаётся старым. Субтитры `tools/skit/mix.py:33` читают именно это поле. Также при совпадении ключа не обновляется who. Нужно раздельно кешировать аудио и обновлять метаданные текущей реплики.

### P2 — зависимость цветовой кривой не зафиксирована в отчёте сборки

`tools/skit/assemble_study.py:120` вызывает ChaseLook, который создаёт Grade (`tools/skit/chase_look.py:7`). `tools/skit/grade.py:64` читает глобальный `_game/study/grade_target.json` или генерирует его из внешних образцов. Отчёт сборки фиксирует кадры, WAV и look-reference PNG (`tools/skit/assemble_study.py:133`–138), но не этот target и не получившуюся LUT. При изменении target те же recipe/PNG/WAV не определяют прежний результат. Докстрока «no local-script dependency» верна для скриптов, но не означает самодостаточность рецепта и его перечисленных ресурсов. Нужна фиксация target/LUT и версий обработки.

## Проверки и ограничения, которые нельзя выдавать за полную приёмку

- `tools/check.py:37`, `tools/check.py:48`, `tools/check.py:57`: пропуски из-за ресурсов не увеличивают fails, поэтому «всё в порядке» не гарантирует, что были проверены сценки. При неизвестном фильтре episodes может оказаться пустым, а сценки с фильтром вообще не запускаются (`tools/check.py:32`, `tools/check.py:46`).
- `tools/check.py:24`: поиск зависимости от игры зависит от форматирования JSON (`"type": "model"`), а проверка наличия ресурсов сводится к существованию `_game`. Он не проверяет содержимое GLB и не является общим unit-test runner. Прямых вызовов assemble_study, chase_audio, datamodel, сценической математики в нём нет.
- `tools/dota_engine/anims.py:58`: rotation выбирается по следующему ключу searchsorted, без интерполяции; `tools/dota_engine/anims.py:102` считает опорой нижние 15% диапазона кости. `stride` — оценка, а не гарантия неподвижной подошвы. Это расходится с категоричностью комментария строки 93. Поля matrix/byteStride/sparse и режимы интерполяции не обрабатываются (`tools/dota_engine/anims.py:37`, `tools/dota_engine/anims.py:75`); универсальным glTF reader его считать нельзя.
- `tools/dota_engine/stage.py:126`: диагностика максимум 10 Гц; рамки и расстояния корней не проверяют одежду, скиннинг, оружие или субкадры. `tools/skit/skit.py:627` выводит только часть проблем для Blender и продолжает работу.
- `tools/dota_engine/framing.py:243` решает план на начале, затем выполняет наезд без повторного выбора варианта. `_best` допускает другую сторону линии и даже первый вариант с помехой (`tools/dota_engine/framing.py:142`). Это полезный подбор кандидата, не строгий запрет нарушений.
- `tools/dota_engine/addon_game_mode.lua:297` ставит root-позу и сбрасывает sequence; `A8_Pose` не выставляет фазу skeletal animation по t (`tools/dota_engine/addon_game_mode.lua:142`). Команда a8_t не является точным seek произвольной анимации. Сервер прекращает проигрывание, но клиентский tick не получает команды stop: `tools/dota_engine/a8_cam.js:33`, `tools/dota_engine/addon_game_mode.lua:297`; ручная камера во время проигрывания может быть снова заменена следующим клиентским tick. Поведение движка не проверялось.
- `tools/dota_engine/anim_to_dmx.py:86`, `tools/dota_engine/anim_to_dmx.py:94`: ошибки переноса стойки печатаются, но порога отказа перед записью DMX нет. Зацикливание пропущенных костей опирается на NI-1 (`tools/dota_engine/anim_to_dmx.py:108`); NI=1 не обработан.
- `tools/dota_engine/record.sh:75` подавляет не только отсутствие ffprobe, но и ошибку assert длительности. Лист просмотра ограничен первыми 24 кадрами при fps=2 — первыми 12 секундами (`tools/dota_engine/record.sh:82`). `sky_comp.py` при ненайденной границе продолжает с первых NEED кадров, при отрицательном start повторяет первый (`tools/dota_engine/sky_comp.py:32`–38). Это fallback, не подтверждение правильного монтажа.
- `tools/skit/assemble_study.py:67` декодирует в stereo принудительно: такая QA не доказывает исходное число каналов MP4. `--validate-only` проверяет существование WAV, но не его декодирование, длительность или громкость (`tools/skit/assemble_study.py:91`, `tools/skit/assemble_study.py:107`). Проверка яркости 90×160 и повторов не является визуальной приёмкой.
- `tools/skit/chase_audio.py:138` и `tools/skit/chase_camera_audio.py:111` используют assert для обязательных проверок; запуск Python с `-O` снимает их. Обычный документированный запуск без `-O` этого недостатка не проявляет. `chase_audio` требует, чтобы voice-null участок не содержал других cue, иначе его собственная проверка не пройдёт (`tools/skit/chase_audio.py:137`).
- `tools/skit/chase_camera_audio.py:18`, `tools/skit/chase_camera_audio.py:44`, `tools/skit/chase_camera_audio.py:121`: утилита рассчитана на конкретный план 4.8–8.0 с, 30 fps и 15 контактов. Положение источника — root героя в момент события, не стопа и не непрерывная акустическая траектория. Изменения этого файла не выполнялись.
- `tools/skit/mix.py:148`, `tools/skit/grade.py:117` ждут кодер, но не проверяют его returncode перед сообщением «готово». В ряде export-утилит существование старого файла заменяет контроль успешности новой операции; например `tools/skit/hero_render.py:19` и `tools/dota_engine/anims.py:22` кешируют по пути без версии VPK/S2V.
- `tools/skit/voices.py:65` умеет читать ключ из Windows registry, но `engine()` в строке 100 выбирает Fish только по окружению; для обычного fish-голоса registry-only ключ не активирует движок. Для `ref` отдельная ветка строк 137–138 это учитывает.
- `tools/dota_engine/water_map.py:36`: эрозия не считает область за рамкой изображения сушей. Если маска целиком true, она никогда не уменьшится. На фактической карте такой вход не проверен. `ground_map.py:73` ограничивает индексы, но не веса билинейной интерполяции: за пределами карты h экстраполируется, хотя code возвращает занято.
