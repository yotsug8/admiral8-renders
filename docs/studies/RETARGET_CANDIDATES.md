# Retarget: кандидат для короткой пробы Blender 5.2

Дата проверки: 01.11.2026. **Выбран Retarget 5.2.0 (KBSBAUDRICE)** для будущей изолированной пробы. Основание — просмотренный путь binding → bake с API action slots и отсутствие найденного собственного сетевого установщика. Это **статический отбор, не подтверждение работоспособности или безопасности**. Blender и аддоны не запускались, ничего не установлено; smoke-test ниже ещё не выполнен. Рассмотрены ровно два кандидата, независимо от известности или корпоративного происхождения.

## Что именно прочитано

**Retarget.** [Release asset `retarget.zip`](https://github.com/KBSBAUDRICE/Retarget/releases/download/v5.2.0/retarget.zip): 225631 байт; SHA256 `521ec8ff5c2373893ea8022b3f71d27ed191fb73f3a5634cac31585e0dcb7af3`. Фактический размер и SHA256 совпали с [GitHub release API](https://api.github.com/repos/KBSBAUDRICE/Retarget/releases/latest). Архив прочитан в памяти; сохранены только текстовые файлы с дополнительным расширением `.txt` в `_game/study/retarget_candidates/retarget_v5.2.0/`. Бинарники и сам ZIP не сохранены. Официальная карточка связывает расширение с этим upstream; **тождество архива с пакетом Blender Extensions не проверено**. Для воспроизводимости нужен именно этот asset/hash, не автоматически обновлённая версия и не GitHub Source code ZIP.

Прочитаны manifest, регистрация, импорты и релевантные участки binding/bake/presets; выполнен поиск сети и исполнения по всем сохранённым Python-файлам. Пути и строки ниже — внутри release asset (в локальных именах `/` заменён на `__`, добавлен `.txt`):

- `blender_manifest.toml:1–13`: минимальная версия, лицензия, только permission `files`; отсутствие network permission не является песочницей. Старое `bl_info.version = (1,0,0)` в `__init__.py` расходится с manifest; для выбранного extension версия берётся из manifest и закрепляется хешем.
- `operators.py:7275` — `ConstrainToArmature`: выбранные rig привязываются к **активному донору**. Создание helper bones около 9515, `COPY_ROTATION`/`COPY_LOCATION` и назначение target/subtarget около 9820–9900. Это существующий constraint-based retarget, не новый самописный решатель.
- `operators.py:10413`, `10875–11139` — `BakeConstrainedActions` → `bone_utils.bake_anim`. `bone_utils.py:1166–1290` — назначение action/slot и создание F-curves; `1293–1603` — выборка матриц, ключи, группировка/очистка через channelbag, сохранение непрерывности quaternion/Euler.
- Ограничение: `get_action_fcurves` возвращает кривые **первого OBJECT-слота**; `assign_action_to_animdata` при отсутствии активного слота выбирает первый suitable. Некоторые исключения подавляются. Поэтому наличие API слотов не доказывает правильный выбор данных или успешный bake.
- `operators.py:23` → `fbx_helper.py:1–3`: импорт `io_scene_fbx` без защиты; отказ загрузки возможен даже при тесте без FBX. `operators.py:5682` — локальный импорт Rigify для конверсии. Эти зависимости не устанавливались и их доступность в целевом процессе не проверялась.
- `__init__.py:42–72`, `preset_handler.py:12–28`: запись bundled presets в пользовательский каталог; одинаковые имена могут перезаписываться. `preset_handler.py:512` читает строки preset как данные, **но отдельный UI-путь `ui.py:924` вызывает `bpy.utils.execfile(filepath)`**. Не загружать чужие presets и не считать Python-пакет безопасным из-за одного permission в manifest. Есть load/depsgraph handlers, Action Manager и инструменты, меняющие сцену вне собственно retarget.
- Опасные для контроля результата defaults: `Fit height = head`, `Apply rotation = True`; bake по умолчанию удаляет помеченные constraints и коллекцию вместе с костями (`operators.py:10413+`). В пробе ниже эти автоматические преобразования/удаления выключены.

**Rokoko.** Прочитаны закреплённые [регистрация](https://github.com/Rokoko/rokoko-studio-live-blender/blob/b031e5a001b3d87e62359d18159c4e4ab479c732/__init__.py), [retarget](https://github.com/Rokoko/rokoko-studio-live-blender/blob/b031e5a001b3d87e62359d18159c4e4ab479c732/operators/retargeting.py), [library manager](https://github.com/Rokoko/rokoko-studio-live-blender/blob/b031e5a001b3d87e62359d18159c4e4ab479c732/core/library_manager.py), [install operator](https://github.com/Rokoko/rokoko-studio-live-blender/blob/b031e5a001b3d87e62359d18159c4e4ab479c732/operators/login.py), [updater](https://github.com/Rokoko/rokoko-studio-live-blender/blob/b031e5a001b3d87e62359d18159c4e4ab479c732/updater.py), updater_ops, login manager, login panel, LICENSE и version_compatibility. Копии `.txt` — `_game/study/retarget_candidates/rokoko/`.

`operators/retargeting.py:367,470–510` подтверждает legacy API в 1.4.3. Для ветки 1.4.4 просмотрены [обновлённый retarget](https://github.com/Rokoko/rokoko-studio-live-blender/blob/650cb0ed9c80a5ac506d52d716af3be4d2ba0888/operators/retargeting.py), [core/utils.py](https://github.com/Rokoko/rokoko-studio-live-blender/blob/650cb0ed9c80a5ac506d52d716af3be4d2ba0888/core/utils.py) и `__init__.py`; это улучшение учитывается, но не объявляется выпущенным/проверенным решением. Полный аудит этой ветки не выполнялся. В 1.4.3 `panels/login.py:16` запускает auto-check, `updater.py:132,336,468` отключает проверку TLS в default context; обновление файлов и установка pip-библиотек являются отдельными пользовательскими действиями, **не доказанной безусловной автоустановкой**. `__init__.py` вызывает auto-login при загруженных библиотеках. Публичные retarget-операторы зарегистрированы и без входа, но это не подтверждает пригодность штатного UI без аккаунта.

Контрольная первичная документация Blender: [переход на Slotted Actions](https://developer.blender.org/docs/release_notes/4.4/upgrading/slotted_actions/) объясняет channelbags и удаление legacy API в 5.0; [ActionKeyframeStrip](https://docs.blender.org/api/current/bpy.types.ActionKeyframeStrip.html) описывает `channelbag(slot)`. Фактическое исполнение на конкретном build Blender 5.2 остаётся обязательной следующей проверкой. Статический поиск не является полным аудитом безопасности или лицензий всех заимствованных компонентов.

## Будущий smoke-test: 2 секунды, одна копия Пуджа

Предварительная проверка дополнительного компьютера: Blender 5.2.0 LTS,
build `fbe6228777e7`, `--factory-startup`; `find_spec` обнаружил
`io_scene_fbx` и `rigify` в `scripts/addons_core`. Код выхода 0,
локальный JSON `_game/study/retarget_preflight/preflight.json`.
Это подтверждение наличия модулей от исполнителя, не тест импорта или
запуска Retarget; на основном компьютере пакет ещё не выполнялся.

**Ещё не выполнялся.** Следующий шаг — изолированная проба по закреплённому пакету, без установки в рабочий профиль и без изменений производственной сцены:

1. Отдельный процесс Blender **5.2 с записанным build hash**, временный профиль/каталоги CONFIG, SCRIPTS и EXTENSIONS; исходящие соединения запрещены на уровне среды, обновления extension выключены. Auto Run Python Scripts выключен (это не блокирует код включённого аддона). Только проверенный asset/hash. До включения проверить наличие `io_scene_fbx`; при отсутствии — остановка и запись зависимости, без pip/доустановок/патча наугад. Rigify для этой пробы не нужен.
2. Открыть **копию** `_game/study/foundations/reach_witness/point_A.blend` в `_game/study/retarget_smoke/`; оригинал защитить и сверить SHA256 до/после. Состав исходника описан в [CHARACTER_OVERLAP.md](CHARACTER_OVERLAP.md): Пудж, одежда, крюк; цепочка `root → spine1 → spine2 → spine3 → neck1 → head`. Отделить actions/armature/mesh data копии, заморозить прежние action/NLA в позе кадра 0; связи одежды/крюка сохранить. Не использовать актуальную сцену калибровки глаз.
3. Донор — отдельная голая armature из этих шести костей, с теми же rest-матрицами и иерархией, но именами `SRC_*`; никаких скачанных mocap/пресетов. Единственный новый OBJECT-slot. 30 fps, кадры **1–60** (2 с): ключи 1/16/31/46/60; `spine2` — 0/+4°/0/−4°/0 вокруг явно записанной локальной оси наклона, `neck1` — 0/−3°/0/+3°/0 вокруг локальной оси поворота головы; линейная интерполяция. Root, ноги и лицо неподвижны. Это намеренно узкий тест переноса верхней части тела с известным ожидаемым движением.
4. Вручную сопоставить шесть костей через поля mapping, без исполнения `.py`-presets. Выбрать копию Пуджа, последним активным — **донор** (`Bind To`). `Bind to Active Armature`: Copy Rotation on, Copy Location/Scale off, No Root; Fit height None, Apply rotation/центрирование/Match Object Transform off; исключить IK/FK-конверсию, Fix Foot, floating bones и автоподгонку. Начальная rest-ориентация одинакова. Записать список новых helper bones/constraints и настройки; проверить, что изменились только назначенные цепочки.
5. До bake сохранить evaluated world-матрицы шести костей на всех 60 кадрах. На Пудже вызвать `Bake Constrained Actions`: Custom Start/End 1/60, Step 1, LINEAR, Bake on; Include Similar Action off, Use Current Action off, Clear original Action Users off, Delete Constraint/Retarget Collection off. Убедиться, что создан отдельный action с назначенным OBJECT-slot и непустыми кривыми нужных костей. Затем отключить **только constraints, добавленные пробой**, убрать влияние донора и повторить измерения.
6. Критерии pass: нет исключений/пропусков каналов; baked playback совпадает с live на всех 60 целых кадрах (предлагаемые допуски 0,1 мм и 0,05°); после сохранения/повторного открытия с выключенным аддоном сохраняются action/slot и те же матрицы. На шаге 0,25 кадра проверить конечные значения, scale и отсутствие одиночных скачков; посмотреть все 60 кадров спереди и 3/4, крайние позы крупно — кожа, ворот/одежда, крюк, силуэт. Исходный файл и неназначенные actions/слоты не изменены. При провале сохранить причину и остановиться, не писать новый решатель.

Результат будущей пробы: `scene.blend`, параметры build/asset/mapping, численный отчёт до/после bake/reopen и два коротких viewport-превью в `_game/study/retarget_smoke/`. Даже pass докажет лишь binding/bake/save одного single-slot rig при совпадающем rest pose; **не** полноценный mocap с другими пропорциями, root motion, опору ног, multi-slot/NLA, пальцы, лицо или художественное качество движения. Общие документы, код проекта, `check.py` и commit в этой задаче не затрагивались.
