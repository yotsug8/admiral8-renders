# Независимый поворот головы: коррекция составной поверхности

Дата: 02.11.2026. Инструмент: `tools/blender/study_neck_corrective.py`.

**Ограниченный результат:** ранее отклонённая последовательность поворота
головы Пуджа проходит проверку деформации после коррекции поверхности.
Сохранены исходные позы, тайминг, материалы и свет. Это не новая готовая
актёрская сцена и не универсальное исправление скелетов. Производственный
сборщик автоматически не меняется: объединение частей требует адаптации
поиска объектов и отдельной проверки конкретного лица/костюма.

## Причина и выбор решения

На участке за ухом соседние вершины следуют преимущественно разным костям:
`spine3` и `head`. Проблема подтверждена в локальной игровой выгрузке;
смена подготовленной копии на найденный GLB не меняет эти веса.
Сравнение источников и ограничения — [PUDGE_SOURCE_AUDIT](PUDGE_SOURCE_AUDIT.md).
Это не утверждение о поведении исходного авторского rig Valve в игре.

Использованы штатные средства Blender, без скачивания аддонов:
объединение объектов, постоянное соединение совпадающих вершин и
[Corrective Smooth](https://docs.blender.org/manual/en/4.2/modeling/modifiers/deform/corrective_smooth.html).
Совместимость проверена непосредственно в Blender 5.2.3.

| Проверенный вариант | Результат |
|---|---|
| Исходная привязка | На проблемном кадре площадь грани сокращается до 10,3% |
| Preserve Volume / dual quaternion | Изменил исходную форму на 0,0502 единицы; проблему не устранил |
| Corrective Smooth отдельно на голове и теле | Убирает сжатие, но раскрывает стык примерно на 0,055 единицы — отклонён |
| Запрет коррекции на точках стыка | Стык сохраняется, но исходная складка остаётся — отклонён |
| Объединение + динамический Weld | Повороты проходят; моргание меняет топологию и нарушает привязку коррекции — отклонён |
| Постоянная сшивка только стыка + Corrective Smooth | Топология стабильна; поворот проходит, но без маски коррекция ослабляла веки и брови |
| Та же сшивка с защитой мимики | Текущий проверенный вариант |

Пороги проверки кожи не увеличивались. Последующие запуски проверяли
конкретные побочные эффекты, а не перебирали оформление или малые углы.

## Метод

1. Проверить общий Armature, совпадение viewport/render-модификаторов,
   отсутствие отдельных shape keys тела. Исходные бинарные файлы не изменять.
2. Найти 16 пар совпадающих точек головы и верхней части тела. Объединить
   копии, постоянно сшить только эти точки с допуском `1e-5`. Не соединять
   соприкасающиеся веки/губы динамически на каждом кадре. После операции
   1015 вершин вместо 1031; все 44 формы, включая Basis, остаются.
3. Добавить Corrective Smooth: BIND в исходной позе, LENGTH_WEIGHTED,
   factor 0,5, iterations 5, Pin Boundaries. Исходная поверхность сохраняется.
4. Защитить вершины, участвующие в `eyeClosed`/`browLowerer`, и соседнее кольцо;
   следующее кольцо получает половинное влияние. Это сохраняет мимику,
   не возвращая резкую границу по исходным весам шеи.
5. Сохранить, открыть заново, проверить движение и выражения. При отказе
   завершиться с ошибкой до рендера. Не устанавливать этот метод в общий
   конвейер только на основании одной пробы.

## Измерения и пределы

Результат: `_game/study/neck_methods/delivery01/scene.blend`.
573 отсчёта через четверть кадра, исходные 144 кадра / 30 fps:

- Изменение нейтральной поверхности — менее `5,4e-7` единицы Blender.
- Минимальная относительная площадь треугольника — **0,2715** при пороге 0,2;
  максимальное отношение длины ребра — **1,4266** при пороге 1,8 и
  дополнительном абсолютном условии прироста. Топология во всех отсчётах совпала.
- Контролируются также 22 совпадения с нижней частью тела и одно с поясом;
  максимальное изменение зазора — `2,4e-7` единицы. Это не поиск всех
  возможных пересечений одежды/оружия и не доказательство физического баланса.
- Три выражения на f0, f39 и f96: моргание, `jawOpen=0,2`, `browLowerer=0,4`.
  Максимальная разница движения век после коррекции — около `3,4e-5`,
  бровей — 0; амплитуды этих выражений сохраняются. Для рта отличие до
  0,0083 при исходной амплитуде 0,0743; этот остаток не называется нулевым.
  Проверка использует 20% амплитуды самого выражения, а не высоты героя.
- Форма отдельных точек шва зависит от лицевых ключей: до 0,0436 единицы
  в одном из 44 исходных ключей. Постоянная сшивка делает точку общей.
  Все сочетания визем, сильные гримасы и исходные предельные ключи **не проверены**.
- Сохранность имён shape keys не равняется сохранности их художественного
  результата. Важно повторять проверку после нового выражения/костюма.

Смена активного направления внимания теперь возможна в исходной малой
пробе. История, характер, сильные повороты, липсинк, все самопересечения
и перенос на другого героя остаются отдельными задачами.

## Повторение

Нужна локальная контрольная сцена с исходной отклонённой анимацией:
`_game/study/character_intent/motion01/scene.blend`, SHA256
`2d813cf246271c0d52bc01f9815b9296ab69e8dd3d43fa9b3af666db249d3daf`.
Её подготовка и исходный ресурс описаны в [CHARACTER_INTENT](CHARACTER_INTENT.md).
Это внешний игровой ресурс, в main не включается. Контрольная сцена
сохраняется как отрицательная проба; удалять её как временный дубль нельзя.

```powershell
$env:BLENDER = py -3.11 -B -c "from tools.paths import BLENDER; print(BLENDER)"
$env:BLENDER_USER_CONFIG = "$PWD/_game/study/neck_methods/env/config"
$env:BLENDER_USER_SCRIPTS = "$PWD/_game/study/neck_methods/env/scripts"
$env:BLENDER_USER_EXTENSIONS = "$PWD/_game/study/neck_methods/env/extensions"
$env:BLENDER_USER_DATAFILES = "$PWD/_game/study/neck_methods/env/datafiles"
& $env:BLENDER -b --factory-startup --disable-autoexec -t 4 --python-exit-code 2 `
  -P tools/blender/study_neck_corrective.py -- `
  --source _game/study/character_intent/motion01/scene.blend `
  --out _game/study/neck_methods/repeat01 --render --motion
```

Папка результата должна быть новой. Без флагов рендера выполняются только
подготовка и проверки. `--render` — пять пар одинаковых крупных кадров до/после;
`--motion` — 144 кадра общего плана и 144 кадра детали. Без звука.
Камера детали охватывает всю траекторию головы с запасом 16% по размеру.
Для уже проверенной сцены `--detail-only` пересчитывает только крупный план
в `motion_detail_framed`, сверив хеши сцены и исходника; остальные кадры
повторно не рендерятся. Выходная папка кадров должна отсутствовать.

Сведение: объединить соответствующие PNG из `motion_front` и `motion_detail`
по горизонтали, без изменения размера (каждый 480×480), в новую папку
`comparison/frames/frame_0000.png` … `frame_0143.png`. Для текущей выдачи
второй вид — `motion_detail_framed`, папка сравнения — `comparison_framed`.
Перед объединением требовать `audit.json: passed=true`, наличие всех 144
кадров обоих видов и совпадение SHA256 сцены с `scene_sha256` отчёта.
Сохранить рядом с `frames` файл `audit.json` с `passed=true` и хешем сцены.
Затем выполнить:

