# 3D в движке доты

Картинка 1:1 как в игре. Сцену ставит площадка (Python), играет мод-режиссёр `admiral8`, кадры пишет дота. Используется для проверок постановки и для роликов «эксперимент в игре». Нужен ПК с дотой и Workshop Tools.

## Пути
Все пути — `tools/paths.py`, свой ПК — переменными окружения: `DOTA_ROOT` (папка «dota 2 beta»), `S2V` (Source2Viewer-CLI), `BLENDER`. Скрипты `.sh` берут `DOTA_ROOT` так же.
- Мод: игра — `game/dota_addons/admiral8`, исходники моделей и Panorama — `content/dota_addons/admiral8`. Копии скриптов мода — `tools/dota_engine/` (addon_game_mode.lua, a8_cam.js, custom_ui_manifest.xml).
- Файлы игры не коммитить: выгрузки — в `_game/` (в .gitignore).

## Запуск и консоль
- `dota2.exe -tools -novid -condebug -console -netconport 29001 -windowed -noborder -w 1080 -h 1920 -nojoy +engine_no_focus_sleep 0 +sv_cheats 1 +dota_launch_custom_game admiral8 dota`.
- Команды: `py -3.11 tools/dota_engine/dota_console.py "команда"` (сетевая консоль есть только с `-tools`). Лог — `game/dota/console.log`.
- Окно рисует кадры только на переднем плане: `focus.ps1` выводит его вперёд и печатает `fg=True`. Запускать из Bash-инструмента (bash, запущенный из PowerShell, уводит фокус). Без переднего плана снимки чёрные, запись — «0 frames».
- Команды мода: `a8_t <сек>` — кадр сцены, `a8_play` — проиграть, `a8_reload` — перечитать сцену, `a8_cam x y z дальность наклон поворот`, `a8_time 0..1`, `a8_where` (руны, фонтаны, здания), `a8_pos` — где актёры, `a8_anims <модель> <имена>` — длительности, `a8_fx <частица> [x y z]`, `a8_map` — высоты и проходимость. `screenshot`/`startmovie` — только из консоли.
- **После работы вернуть настройки доты владельца** (`userdata/<id>/570/local/cfg`): перед сессией скопировать файлы, после выхода сравнить. Запуск с `-w 1080 -h 1920` портит video.txt (разрешение, полный экран), `engine_no_focus_sleep`, `fps_max`, `dota_camera_edgemove`, `dota_camera_disable_zoom`.

## Площадка (`tools/dota_engine/stage.py`)
- `st = Stage(cam, dur, ground=Ground(), trees=(cx, cy, r, 0))`; `st.actor(имя, None, motion, [(t, анимация[, скорость])], hero=…, world=[точки карты])`; `st.fx(t, "particles/…vpcf", at=(x, y) или "актёр", to="актёр")`; `st.write()` пишет `scripts/a8_scene.txt` мода, `st.dump_json(…)` — сцену для Blender.
- Актёра можно ставить по кадру (`anchors` — x вправо, y вниз, ±0.75 — края ролика): точку на карте считает проекция камеры `project.py`. Решатель раздвигает фигуры и проверяет по всей длине: не касаются (185 ед.), не обрезаны краем, не сливаются, не слишком крупные, не в скале/дереве/здании, луч камеры к фигуре свободен; в реке — в воде.
- `motion(t, pts) → (x, y, z, наклон, поворот, крен)`; движение по точкам — `path(точки, скорость)`. Скорость шага анимации (чтобы ноги не скользили) — `py -3.11 tools/dota_engine/anims.py <герой> run`.
- Тело и части героя — из items_game (`hero_parts.py`), любая модель — `model=`/`parts=`.
- Новые модели и частицы грузятся при запуске доты из файла сцены: сначала записать сцену, потом запускать игру.
- Пример постановки целиком — `tools/skit/skit.py` (функция `build`).

## Автокамера (`framing.py`)
`fr = Framer(st, line=(a, b), side=±1); st.cam = fr.cut([(t, fr.over(x, y)), (t, fr.close(x)), (t, fr.two(a, b)), (t, fr.wide(…))])` — операторские планы формулами. Проверяет деревья на луче, камеру в скале/здании/под землёй, не ближе ширины героя, не смотреть вверх (дота отвергает отрицательный наклон); если план не встаёт — запасной.

## Свои анимации героя
1. `py -3.11 tools/dota_engine/troupe.py <герои>` — разбор модели в `content/…/models/a8/<герой>/`, рост, высота головы, ширина, челюсть, стойка-образец → `_game/data/troupe.json`.
2. Анимации пишет скрипт Blender (задаёт `CUSTOM {имя: действие}` и `LOOPING`; пример — `tools/blender/skit_talk.py`): поза от игровой стойки, повороты суставов в мире, запекание.
3. DMX: `blender -b --factory-startup -P tools/dota_engine/anim_to_dmx.py -- <папка модели в content> <glb героя> <префикс> <скрипт> [стойка]`, затем `troupe.add_anims(герой, {имя: зацикленность})` — AnimFile в vmdl и сборка `resourcecompiler`.
- Длительность клипа в DMX — только типом `datamodel.Time`. Разовая анимация, кончившись, возвращает модель в стойку — делать её длиннее нужного. Наклон к камере не читается — ставить героя боком. Скорость анимации — третьим числом `(t, анимация, скорость)`.

## Кадры и запись
- Кадры до записи: `tools/dota_engine/shots.sh <имя> <сек…>`; глазами — `a8_t <сек>` + `screenshot`.
- Запись: `bash tools/dota_engine/record.sh <имя>` (~20 с окно впереди, мышь не трогать). startmovie и a8_play — одной строкой, `host_framerate 30` + `fps_max 20` привязывают кадры к тикам; кадров ровно длина × 30. Небо в чёрную пустоту подставляет `sky_comp.py`.

## Карта
- Оси: игра x = −Blender_y·39.37, y = Blender_x·39.37. Камера: поворот 0 — смотрим на север; модель с yaw 270 смотрит в камеру.
- Земля, деревья, здания — `_game/data/ground.npz`, `buildings.txt` (`ground_map.py --grab` из игры). Вода — `water_map.py`; вода по щиколотку (≈16 ед.): стоящих опускать на −45, лежащих держать у поверхности.
- Проекция откалибрована (`calib.py` + `calib_measure.py`): угол обзора по вертикали 66,3°. Высоту точки взгляда дота берёт с земли.

## Грабли
- Деревья с морфингом (`*_vmorf`) в пользовательской игре не рисуются — мод ставит кино-версии `*_sfm.vmdl` по `a8_trees.txt`; деревья между камерой и сценой пропускаются; камеру ставить над открытым местом.
- Неба на карте нет: пишем без тумана (`fog_enable 0`), небо подставляет `sky_comp.py`. Низкий наклон (19) — больше неба; ниже 16 обрезаются фигуры.
- Камера ставится в интерфейсе каждый кадр по таблице ключей; плавность −1 (0 — склейки «плывут»). Изменённый `a8_cam.js` подхватывается только после полного перезапуска доты.
- `SetPlaybackRate` у prop_dynamic — только входом сущности. При записи выключать `r_depth_of_field`.
- Анимации с собственными частицами (кровь, посторонние фигуры, пыль) проверять кадрами.
