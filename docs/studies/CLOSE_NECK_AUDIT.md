# Ограниченный аудит legacy close_neck

CPU-проверка Blender 5.2.0 LTS, build `fbe6228777e7`. Производственный
`tools/blender/render_scene.py` не изменён; модуль целиком не импортируется.
Скрипт извлекает через AST только функцию и проверяет её SHA256:
`3ebd652e2dd38bdc133290c421691520e9592e9c184d20b5dbc2feff93bbd659`.
Эта функция совпала с main на момент аудита (Git blob всего render_scene.py:
`42b4356aee1f58f6cebafbab2eee7b7901f5a072`).

## Ближайший конкретный вывод

Подтверждён ограниченный дефект: если у головы **нет deform layer**, вызов
`bm.verts.layers.deform.verify()` после сохранения ссылок на вершины кромки
делает эти ссылки недействительными. В обеих синтетических сетках 37 из 37
ранее полученных BMVert стали `is_valid=False`. Следующее чтение `v.co`
в исходной функции выбрасывает `ReferenceError: BMesh data of type BMVert has
been removed`. До `bm.to_mesh` выполнение не доходит; исходная mesh и ключи
остаются прежними. Обработчика с `bm.free()` на этом пути нет.

При наличии слоя весов этот дефект не воспроизведён: ссылки действительны,
функция добавляет 18 вершин и 18 граней. Это **не объяснение дефекта Пуджа**:
его настоящая сетка, её слои, позы и модификаторы здесь не проверялись.
Исправление производственной функции не выполнялось.

## Четыре фиксированных случая

Голова: открытый снизу цилиндр, 18 вершин на кольце и верхняя крышка.
Вариант со швами дублирует вершины для каждой грани; координаты всех морфов
на совпадающих вершинах одинаковы. Тело — 54 точки для поиска ближайших
весов. Взвешенный вариант имеет группу neck с весом 1 на всех вершинах.
Во всех случаях есть Basis, A, B; B относителен к A, значения ключей нулевые.

| Сетка | Веса | Вершин до → после | Результат |
|---|---|---|---|
| Обычная | Нет | 37 → 37 | Описанный ReferenceError |
| Разделённая по граням | Нет | 126 → 126 | Описанный ReferenceError |
| Обычная | Есть | 37 → 55 | 18 новых вершин и граней |
| Разделённая по граням | Есть | 126 → 55 | Сварка до 37, затем +18 |

Для успешных случаев проверено:

- `mesh.vertices`, Basis и каждый key_block имеют по 55 элементов;
- mesh и Basis совпадают; координаты всех старых ключей сохранены по
  геометрическому соответствию (ошибка 0); связь B.relative_key=A сохранена;
- новые вершины во всех ключах равны Basis (ошибка 0), наследуют вес 1;
- после remove_doubles все 18 индексов граничных рёбер различны и неотрицательны;
  исходный обход действительно добавляет полное кольцо из 18 вершин;
- у новых граней положительная площадь и наружные нормали: минимальное
  скалярное произведение с радиальным вектором 0,24344145;
- нет manifold-рёбер с несогласованным обходом соседних граней;
  нижнее кольцо из 18 граничных рёбер остаётся открытым.

## Статические ограничения и граница вывода

Функция использует индексы рёбер после remove_doubles без `index_update`.
На этих двух топологиях коллизий индексов и ошибки обхода не обнаружено;
само отсутствие обновления не объявляется подтверждённым дефектом.

Сварка выбирается по базовым координатам; совпадение разных morph delta
на шве не проверяется самой функцией. Проба содержит только одинаковые
значения на дубликатах. Случай разных морфов не исследовался.

Новые вершины получают одинаковые координаты во всех shape layers, то есть
нулевую собственную морф-деформацию. Это буквальное поведение кода;
художественная пригодность перехода не доказана. Функция создаёт юбку вниз
и внутрь, а ближайшее тело служит источником весов, не координат привязки.
Она не закрывает нижнее кольцо крышкой.

Не проверялись настоящий персонаж, активные ненулевые значения морфов,
UV, несколько или незамкнутые кромки, пересечения и результат деформации
в движении. Ни успешные синтетические случаи, ни исключение без весов
не подтверждают качество кожи Пуджа. Перебор прекращён на этом выводе.

## Воспроизведение

```powershell
& $env:BLENDER --background --factory-startup --disable-autoexec --python-exit-code 2 --python tools/blender/study_close_neck_audit.py -- --out _game/study/close_neck_audit/result.json
```

Использовать отдельный локальный профиль Blender через BLENDER_USER_CONFIG,
BLENDER_USER_SCRIPTS, BLENDER_USER_EXTENSIONS и BLENDER_USER_DATAFILES.
Скрипт ничего не рендерит, не сохраняет пользовательские настройки,
не устанавливает зависимости и не загружает игровые ресурсы.

Все утверждения четырёх случаев прошли; числа сохранены в
[close_neck_audit_result.json](close_neck_audit_result.json).
Общий `py -3.11 tools/check.py` запущен, но не выполнен: локальный launcher
ответил `No installed Python found!`. Установка Python не выполнялась;
общий check.py требуется при приёмке на машине с полным окружением.

При интеграции проверка четырёх случаев повторена на Blender 5.2.3:
все утверждения прошли, включая воспроизведение ошибки без весов.
Общий check.py на Python 3.11 выполнен успешно. Производственная функция
и модели не менялись; результат остаётся диагностическим.
