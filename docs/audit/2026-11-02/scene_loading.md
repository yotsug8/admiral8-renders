# F09: готовность GLB, площадки и Lottie

Продолжение [проверки изображений](resource_loading.md). Ошибка обязательного
ресурса должна прерывать подготовку, а не давать неполный кадр.

## Изменения

- `scene.js`: загрузка GLB и карт ограничена 30 секундами. Ошибка зависимости
  из `LoadingManager` отклоняет подготовку, даже если GLTFLoader сам подавил
  ошибку текстуры. Сообщение содержит модель/карту и адрес зависимости.
- Пустой набор частей, некорректный GLB, отсутствующая явно выбранная
  анимация и пустые/неконечные границы модели отклоняются. Если имя анимации
  не задано, прежний выбор первого клипа сохранён; статические модели разрешены.
- Процедурная площадка ждёт декодирования обеих текстур bed/bank. При
  загруженной карте эти невидимые объекты и их текстуры вообще не создаются.
- `scene_lottie.js`: SVG-анимация создаётся на этапе `SCN.load`, до timeline
  и первого seek. Проверяются основные metadata, изображения, DOMLoaded и
  loaded_images; ошибки подготовки и общий таймаут прерывают загрузку.
- Lottie получает копию JSON. Пути картинок разрешаются относительно
  исходного JSON через `assetBase`; Python сохраняет эту директорию при
  `file:`-импорте. При ошибке созданный экземпляр уничтожается, собственные
  обработчики и таймер снимаются. Внутренние методы проверены по vendored
  Lottie light 5.13; при обновлении библиотеки нужны повторные проверки.

## Воспроизведение

```powershell
py -3.11 -B -m unittest tools.test_scene_loading tools.test_lottie_loading tools.test_resolve_scene tools.test_resource_loading -v
py -3.11 tools/check.py
```

Прошли **37 тестов**: 12 GLB/stage/интеграция Lottie, 10 самостоятельных
Lottie, 2 resolve_scene и 13 прежних загрузчиков. Из них 23 новых.
Общий check: **18 выполнено, 0 пропущено, всё в порядке**.

В браузере используются реальные GLTFLoader, TextureLoader и Lottie,
локальный HTTP-сервер и программный WebGL Chromium. Треугольник GLB,
картинки и JSON генерируются в памяти; игровые и внешние сетевые ресурсы,
платная озвучка и тяжёлый рендер не нужны.

Проверены отсутствующие/битые ресурсы, задержанный успех, незавершённые
HTTP-запросы с переводом часов Playwright на 30001 мс, видимые пиксели
GLB и SVG, перемотка Lottie после init, вложенная композиция, относительные
и embedded-пути, сохранность исходного JSON и снятие обработчиков.
Настоящая ошибка неподдерживаемой SVG-камеры проверяет уничтожение Lottie.

## Границы

- Это готовность ресурсов, не художественная оценка или проверка всей
  геометрии, скелетов, шейдеров и игровых моделей. Статическая синтетическая
  карта не подтверждает корректность всех материалов Dota.
- Chromium переиспользует декодированное изображение между HTML и SVG даже
  при `no-store`. Повторный HTTP-запрос не считается обязательным; отдельный
  отказ повторной SVG-загрузки не воспроизведён. Защита по loaded_images
  присутствует, но этот отрицательный сценарий не объявляется проверенным.
- Произвольные внешние CSS, шрифты, footage/audio, expressions и все варианты
  Lottie JSON не покрыты. Внешние Lottie segments явно отклоняются.
- Таймаут GLTF/TextureLoader прекращает ожидание, но не гарантирует отмену
  каждого внутреннего запроса. При ошибке штатный рендер закрывает браузер;
  продолжение работы в той же странице после ошибки не сертифицировано.
- Валидное изображение-заглушка и валидная геометрия неправильного объекта
  не распознаются как ошибка. F09 и полный аудит целиком не закрыты.
