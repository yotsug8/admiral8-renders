# Готовый mocap: осматривание CMU 77_01

Проверен один кандидат для следующей пробы переноса: **3 секунды реального
движения CMU 77_01, «looking around»**, отсчёты AMC 721–900 включительно.
Актёр стоит с согнутыми коленями и поворачивает корпус/голову. Это вырезка
длинной записи, не замкнутый жест с возвращением в исходную позу. Для
вертикально выпрямленного персонажа потребуется другой выбор позы.

Данные импортированы штатным BVH-импортёром Blender 5.2.0 LTS
(`fbe6228777e7`), сохранены и открыты новым процессом. Рендера, переноса
на игрового персонажа и установки зависимостей не было. В исходную ветку
добавлен только этот документ; ресурсы и доказательства передаются отдельно.

## Источники и разрешение

Рассмотрены ровно три релевантных источника:

1. [Bandai Namco Research Motiondataset](https://github.com/BandaiNamcoResearchInc/Bandai-Namco-Research-Motiondataset):
   BVH с лицензией CC BY-NC 4.0. Не выбран для потенциально коммерческого
   ролика. MIT для утилит не меняет лицензию самих движений.
2. [CMU Graphics Lab](https://mocap.cs.cmu.edu/) и
   [официальный FAQ](https://mocap.cs.cmu.edu/faqs.php): разрешены
   использование в коммерческих продуктах, копирование, изменение и
   распространение. **Прямая перепродажа самих данных, в том числе после
   конвертации, запрещена.** Это собственные условия CMU, не CC0.
   [Каталог актёра 77](https://mocap.cs.cmu.edu/search.php?subjectnumber=77)
   определяет название движения и частоту 60 fps.
3. [CGspeed, MotionBuilder-friendly BVH release](https://sites.google.com/a/cgspeed.com/cgspeed/motion-capture/the-motionbuilder-friendly-bvh-conversion-release-of-cmus-motion-capture-database):
   конверсия Bruce Hahne, выпуск 26.06.2010, READMEFIRST v1.1.
   [README конвертера](https://sites.google.com/a/cgspeed.com/cgspeed/motion-capture/the-motionbuilder-friendly-bvh-conversion-release-of-cmus-motion-capture-database/readme-motionbuilder-2010-release)
   не добавляет ограничений. Его старое обобщение об отсутствии ограничений
   не отменяет действующий запрет CMU на прямую перепродажу данных.

Для передачи внутри проекта разрешение есть. При использовании сохранять
источники и условия; рекомендуемое указание происхождения: «Motion capture:
CMU Graphics Lab; NSF EIA-0196217. BVH conversion: Bruce Hahne / CGspeed».
Архив скачан без аккаунта или оплаты. Скрипты из архива не исполнялись.

## Время, единицы и изменения

- ASCII BVH: `HIERARCHY` + `MOTION`, 31 узел, 96 каналов. Root `Hips`:
  XYZ-положение и ZYX-вращение; остальные узлы — ZYX-вращение, градусы.
  Все 1091 строки исходной конверсии имеют 96 конечных чисел.
- AMC содержит 1090 отсчётов. В BVH первая строка — добавленная конвертером
  Т-поза, затем те же 1090 отсчётов. Максимальная разница XYZ корня между
  всеми строками AMC и соответствующими BVH — 0,00005 исходной единицы
  (округление конвертера, около 2,82 мкм после масштабирования).
- **Важная поправка:** BVH заявляет `Frame Time: .0083333` (около 120 fps),
  а первичный каталог для этой записи — **60 fps**. Конвертер описывает
  общую замену частоты на 120. Здесь сохранено число отсчётов и применены
  60 fps из каталога; без поправки движение было бы вдвое быстрее.
  Частота физической съёмки отдельно от каталога не измерялась.
- Вырезка берёт строки движения BVH с индексами 721–900 при нумерации
  с нуля, где индекс 0 — Т-поза. Значения каналов не сглажены и не менялись;
  заменены только количество строк и Frame Time на `1/60`. Т-поза исключена.
- Blender: кадры 1–180, 60 fps, `fps_base=1`; время отсчётов 0–2,983333 с,
  длительность воспроизведения 180/60 = **3 с**. Исходное окно AMC:
  12–14,983333 с. Не интерполировать через добавленную Т-позу.
- Масштаб: ASF `length 0.45`, исходные единицы соответствуют
  `0.0254/0.45 = 0.05644444444444444 м`. Проверен перенос единиц в BVH:
  например, длина бедра ASF 6,97235 и его направление дают BVH OFFSET
  `(2.38468, -6.55187, 0)` с округлением. Корневые позиции также совпадают.
- Импорт: `global_scale=0.0254/0.45`, `axis_forward='-Z'`, `axis_up='Y'`,
  результат в метрических единицах Blender, Z вверх. Корень не центрировался,
  высота пола не исправлялась, циклическое воспроизведение выключено.

## Импорт и проверка

Отдельный заводской процесс, `--background --factory-startup
--disable-autoexec --python-exit-code 2`; каталоги `BLENDER_USER_*`
изолированы в папке задания. Выполнялся только собственный проверочный
скрипт и модуль `io_anim_bvh` из поставки Blender. GPU и рендер не использовались,
Preferences не сохранялись. Первая подготовительная попытка остановилась
до импорта из-за повторной регистрации уже включённого штатного модуля;
после проверки `ImportBVH.is_registered` импорт и повторное открытие прошли.

Основные параметры вызова после очистки заводских объектов и установки fps:

```python
bpy.ops.import_anim.bvh(
    filepath=str(clip), target='ARMATURE', global_scale=0.0254/0.45,
    frame_start=1, use_fps_scale=False, update_scene_fps=False,
    update_scene_duration=False, rotate_mode='NATIVE',
    axis_forward='-Z', axis_up='Y',
)
scene.frame_start, scene.frame_end = 1, 180
```

В сцене один Armature, один action с диапазоном 1–180; нет Text datablocks,
внешних библиотек или drivers у арматуры. Импортёр сообщил о нулевой длине
узлов `Hips`, `Spine1`, `LeftHand`, `RightHand` и создал им отображаемые
кости своим штатным способом. Длина этих служебных костей не является
измерением анатомии; не переносить их длины на целевой rig без проверки.

Сохранены `import.json`, `reopen.json` (иерархия, rest head/tail, время,
масштаб), `poses.json` (180 поз), `ready_motion.blend` и
`clip_contact_sheet.png` (8 скелетных проекций, просмотрены).
В новом процессе проверены все **11160** точек: 180 кадров ×31 кость ×2 конца.
Максимальное расхождение до/после сохранения — **0 м**; rest-иерархия и
координаты совпали точно. Это проверка head/tail, не отдельная проверка
вращения каждой кости вокруг её продольной оси или всех субкадров.

Фактическая иерархия импортированных костей:

```text
Hips
  LHipJoint → LeftUpLeg → LeftLeg → LeftFoot → LeftToeBase
  RHipJoint → RightUpLeg → RightLeg → RightFoot → RightToeBase
  LowerBack → Spine → Spine1
    Neck → Neck1 → Head
    LeftShoulder → LeftArm → LeftForeArm → LeftHand
      LeftFingerBase → LeftHandIndex1
      LThumb
    RightShoulder → RightArm → RightForeArm → RightHand
      RightFingerBase → RightHandIndex1
      RThumb
```

## Границы результата и следующий шаг

Это настоящий готовый mocap, а не синусоидальный тест. В выбранном окне
корень смещается по одной горизонтальной оси в диапазоне около 12,7 см,
голова — около 32 см; на просмотренных скелетных проекциях актёр не делает
шага. Диапазон положения носков по отдельным осям достигает 1,65 см:
идеальная неподвижная опора не заявляется. Метки костей не равны поверхности
стопы; в сцене нет кожи, одежды, пальцевой анимации или пола для контактов.
Согласно CMU, движения пальцев не захватывались, эти каналы не использовать
как достоверную анимацию кистей.

Результат годится для ограниченной следующей пробы Retarget на манекене:
проверить оси/rest-позу и соответствия костей, перенести только выбранные
цепи, затем отдельно проверить стопы и сохранённый action. Качество на
игровом персонаже, отсутствие пересечений и художественная готовность
этим импортом не подтверждены. Локальная папка: `_game/study/ready_motion_clip/`.
