# Аудит видеоконвейера и frontend

Дата: 2026-11-01. Область: только `video.py`, `video.html`, `scene.js`, `scene.css`, `dota_map.js`.

Прочитаны полностью 5 файлов, 3125 строк. Чтение последовательными диапазонами, не только поиском или AST. Все пять SHA256 совпадают с `main_manifest.json`; значения и диапазоны чтения — в `frontend_coverage.json`. Дополнительно прочитаны инструкции проекта, RTK и текущее состояние. Усечённый первоначальный вывод состояния восстановлен отдельным чтением диапазонов. Код не менялся, коммитов нет; проверки проекта, браузер, рендер и Dota не запускались. Ниже — статически доказанные условия, а не результаты визуального прогона. Использование возможностей в остальных частях репозитория не исследовалось: нельзя утверждать, что они нигде не применяются.

## Главные результаты

1. Нарушен контракт `stage.actors[].anim`: Python превращает имя GLB-анимации в объект кадров, JavaScript незаметно выбирает первую анимацию. F01.
2. Скрытие сегмента не гарантирует скрытие клипов/Lottie; явные переходы в темах `k`/`c` оставляют полноэкранные слои поверх материала. F02–F03.
3. Сообщение успешного QA не доказывает покрытие черновика и даже использует расширенную безопасную зону. F04–F05. При этом уже имеется богатый JSON-конструктор, позволяющий не писать отдельную раскладку для каждого ролика.

## Подтверждённые ошибки и пробелы

### F01 — P1: теряется выбранная анимация актёра площадки

Источник: `video.py:586`, `video.py:589`, `scene.js:326`, `scene.js:228`.

`resolve_scene` рекурсивно обходит актёров. Любое строковое поле `anim` преобразуется через `anim_frames`, кроме словаря с `type == model`. У обычного актёра `{hero: ..., anim: "walk"}` такого типа нет. В результате `a.anim` становится `{fps, frames}`, сравнение `a.name === animName` всегда ложно, выбирается `base.animations[0]`. Если одноимённых 2D-кадров нет, дополнительно появляется предупреждение «нет анимации», хотя GLB-клип может существовать.

Исправление: различать контекст 2D-элемента и актёра stage, сохранять строковое имя; неизвестный GLB-клип диагностировать отдельно. Для будущей проверки достаточно проверить форму разрешённого JSON без браузера, затем отдельно выбор клипа.

### F02 — P1: клип/Lottie может просвечивать из неактивного сегмента

Источник: `video.html:887`, `video.html:888`, `scene.js:427`, `scene.js:434`; контраст с уже учтённой проблемой: `video.html:1242`.

`seek` скрывает только родительские `.seg` через `visibility:hidden`, рисует только текущую сцену. У клипа с `hold:false` и у Lottie дочерний контейнер получает собственное `visibility:visible`. CSS позволяет потомку переопределить наследуемое скрытие. Если последний отрисованный кадр предыдущего сегмента оставляет этот контейнер visible, следующая сцена его не обновляет: он продолжает отображаться. Lottie после старта всегда попадает под это условие; клип — если его конец находится позже последнего кадра сегмента. Такой же риск есть при обратном seek. В chronicle уже есть комментарий и обход через `display`, но универсальные медиа его не используют.

Исправление: скрывать неактивные сегменты через `display` либо полностью сбрасывать видимость потомков; учесть обратную перемотку и границы чанков.

### F03 — P1: `theme:k/c` вместе с `transition` закрывает кадр штатным слоем темы

Источник: `video.html:267`, `video.html:269`, `video.html:302`, `video.html:307`, `video.html:308`, `video.html:451`, `video.html:452`, `video.html:898`, `video.html:912`, `video.html:928`.

CSS включает `#ring` для c и `#tide` для k. Их исходное состояние видимое; ring — непрозрачный фон на весь экран, tide — полоса высотой 2500 px с непрозрачным телом. Код, который устанавливает hidden вне стыка и позицию/маску, выполняется только при `!D.transition`. Любое непустое явное `transition` оставляет эти слои в исходном состоянии поверх сегментов. `transit()` меняет сегменты и tflash, но не ring/tide. Условие воспроизведения — тема k или c плюс, например, push.

Исправление: исходно скрытые тематические слои и явное управление режимом перехода независимо от фоновой анимации.

### F04 — P1: черновик пропускает выбранные QA-кадры, но может сообщить успех

Источник: `video.py:746`, `video.py:748`, `video.py:715`, `video.py:761`, `video.py:953`.

Checks вычисляются как `int((start+x)*30)+1`; черновик рендерит только чётные номера `range(0,n,2)`. Проверка вызывается только при точном попадании номера в checks. Пример по формулам кода: один сегмент start=0, dur=4 даёт проверки 37, 67, 106; выполняется только 106. При dur=4.1 проверки 37, 68, 108 выполняются две; покрытие зависит от округления, а не заданных моментов. В частности, тройка нечётных индексов означает отсутствие всех проверок сегмента. Для коротких сегментов также нет ограничения checks границами сегмента/ролика. Пустой набор проблем печатается как «всё в безопасной зоне», число действительно проверенных кадров не контролируется.

Исправление: выбирать checks среди реально выдаваемых кадров, ограничить диапазон, сохранять expected/actual coverage и не объявлять успех при отсутствии проверок.

### F05 — P2: аудит не проверяет заявленные поля и фактическую видимость

Источник: `video.html:29`, `video.html:1334`, `video.html:1335`, `video.html:1338`, `video.html:1341`, `video.html:1352`.

Заявленная безопасная зона x=60..940, y=150..1560, но код допускает x=40..960, y=140..1580. Например текст с left=50 не отмечается. `vis` учитывает лишь собственную opacity, не opacity предков, visibility или перекрытие. Список проверяемых элементов не включает `modelbox` и `animbox`; hero проверяется на пересечение с текстом, но не своим габаритом на выход за зону. Canvas/3D-силуэты, одежду, геометрические пересечения и перекрытие главным объектом эта проверка не подтверждает. Возможны как пропуски, так и ложные пересечения текста из невидимого родителя.

Исправление: единые границы, учёт видимости по дереву, отдельный отчёт непокрытых типов. Не переименовывать ограниченную DOM-проверку в проверку всего видео.

### F06 — P2: запасная озвучка теряет отображаемую форму слов

Источник: `video.py:153`, `video.py:159`, `video.py:316`, `video.py:327`, `video.py:333`, `video.py:605`.

Выбранный дубль и Fish возвращают `align_to_script(text, ...)`; edge-tts получает `say_text(text)` и его слова возвращаются напрямую. Для `{7.33|семь тридцать три}` субтитры запасного голоса становятся «семь тридцать три», а не «7.33». Меняются и cue-слова, рассчитанные на экранную форму. Это также относится к FV_FAKE_TTS через ту же ветку. Исправление: единый этап выравнивания по исходному тексту для всех backend.

### F07 — P2: границы клипа и его звука расходятся

Источник: `video.py:878`, `video.py:903`, `video.py:907`, `scene.js:384`, `scene.js:425`, `scene.js:426`, `scene.js:427`.

Видео использует nullish-выбор `in.at ?? it.at`; звук использует `in.at or it.at`, поэтому `in.at=0` и `it.at=2` дают разные начала. JS циклически повторяет изображение при loop, Python добавляет WAV один раз. При loop плюс hold:false JS всё равно скрывает контейнер после raw>=n: повторение кадров рассчитано, но не видно. WAV также не обрезается концом сегмента: длинный клип продолжит звучать в следующем, хотя сцену уже переключили. Применение child-defaults к элементам происходит только в JS (`scene.js:105`), тогда как обход звуков сырых items их не наследует.

Исправление: один нормализованный контракт начала/конца/loop и child-defaults до подготовки изображения и звука; обрезка и повтор аудио по тому же интервалу.

### F08 — ограничение настройки: направление солнца карты не управляет светом героев

Источник: `scene.js:279`, `dota_map.js:17`.

Вызывающая сторона передаёт `{sun: it.sun_dir}`, то есть контракт здесь согласован. Однако обычный directional light в stage всегда ставится в (6,10,6), `scene.js:271`, и не использует sun_dir. Это не ошибка передачи opts. Ограничение — настройка меняет только multiblend карты, а не освещение героев. При ожидании единого солнца герои и земля освещаются с разных направлений. Нужна явная документация области действия либо синхронизация светильника. Визуальный дефект конкретной сцены не проверялся.

### F09 — P2: отсутствие файла изображения не останавливает подготовку

Источник: `video.py:399`, `video.py:401`, `video.html:840`, `video.html:1078`, `video.html:1079`, `dota_map.js:10`, `dota_map.js:27`.

image_ref только печатает предупреждение; общий загрузчик считает onerror завершением, аудит не проверяет naturalWidth. Поэтому пропавшая иконка может дать пустое место с итоговым успехом QA. buildMosaic у вынесенных из DOM картинок ждёт только onload: ошибка во время ожидания оставляет Promise незавершённым; если broken image уже complete, он проходит дальше к drawImage. Карта тоже считает неудачную загрузку текстуры успешным завершением ready, без списка пропусков. Исправление: явный список ошибок ресурсов и отказ/обозначенный degraded-режим до выдачи результата.

### F10 — P2: общая рабочая папка небезопасна для двух независимых рендеров

Источник: `video.py:43`, `video.py:600`, `video.py:752`, `video.py:757`, `video.py:933`, `video.py:1062`.

Все запуски пишут одинаковые vN.mp3, chunk_N.mp4, chunks.txt, video.mp4, audio.wav; audition удаляет v*.mp3. Встроенные процессы одного render делят чанки по номеру корректно, но два самостоятельных запуска конфликтуют. Это подтверждает необходимость запрета общего temp в параллельной работе. Исправление: отдельный каталог запуска, общими оставить только корректно адресуемые кэши.

### F11 — P2: незавершённый кэш видео принимается за готовый

Источник: `video.py:509`, `video.py:510`, `video.py:516`, `video.py:519`, `scene.js:424`.

Каталог создаётся до ffmpeg. После неудачи/прерывания следующий вызов видит exists и не извлекает кадры заново, даже если кадров нет или они неполны. Пустой набор в JS просто пропускается. Ключ с size/mtime защищает от замены исходного клипа, но не от недописанного результата. Исправление: временный каталог и маркер завершения после успешного ffmpeg с проверкой числа кадров.

## Источники данных, доверие и безопасность

- Поток: JSON выпуска → prepare/resolve_scene → сериализованные сегменты → init → SCN либо готовая раскладка → seek → PNG в ffmpeg → микс и AAC. Узлы: `video.py:593`, `video.py:738`, `video.py:702`, `video.py:711`, `video.py:935`, `video.py:939`, `video.html:532`, `video.html:875`.
- Справочники: локальный dotaconstants, затем бессрочный cache, затем GitHub master (`video.py:77`). Картинки: Steam CDN, cache и placeholder (`video.py:92`, `video.py:344`, `video.py:366`). Это не источник подтверждения актуальных механик: версия справочника не закреплена и возраст кэша не проверяется.
- Речь: выбранные локальные записи, Fish с настройками окружения и кэшем, edge fallback; тайминги faster-whisper small и кэш по содержимому (`video.py:223`, `video.py:239`, `video.py:310`). Секреты не передаются в JS-данные; отчёт не содержит их значений. Текст уходит внешнему TTS при выбранном сетевом пути; предупреждения могут включать текст ответа сервиса (`video.py:199`, `video.py:206`).
- Локальные ресурсы: assets, `_game/img`, `_game/models`, `_game/maps`, каталог мемов, Lottie JSON (`video.py:391`, `video.py:529`, `video.py:558`, `video.py:579`, `scene.js:277`). `FV_GAME_DIR` учитывается для img/models, но карта всегда читается из `_game/maps` относительно HTTP-корня: ограничение переносимости (`scene.js:277`).
- S01 — условный риск недоверенного JSON: текст напрямую включается в innerHTML в `scene.js:12`, `scene.js:58`, `video.html:470`, `video.html:600`, `video.html:810`, `video.html:1320`; accText экранирует текст (`video.html:529`), но применяется не повсюду. Текст с HTML-обработчиком события может выполняться как JS. Chromium запускается с разрешённым file-access и отключённой web-security (`video.py:698`), а локальный сервер отдаёт весь корень репозитория (`video.py:733`). Сочетание расширяет последствия импорта чужого сценария до чтения доступных файлов/сетевых обращений. Это не доказательство утечки и не утверждение, что доверенные локальные выпуски атакуют систему. Нужна явная граница доверия, экранирование текстовых полей и узкий каталог ресурсов.
- S02 — пути file/src, voice_file, hero и lottie не ограничиваются корнем через resolve/relative_to (`video.py:314`, `video.py:397`, `video.py:503`, `video.py:572`, `video.py:580`). JSON должен считаться доверенным управляющим входом, не безопасным форматом обмена с произвольным автором. subprocess использует список аргументов, а не shell=True; оболочечная инъекция здесь не установлена.
- Локальный HTTP-сервер слушает только loopback (`video.py:736`), но не закрывается через shutdown/server_close; повторные render в audition оставляют серверы до завершения процесса (`video.py:1066`). Это ресурсный дефект, не публично открытый сетевой порт.

## Дублирование, старые ветви и ограничения доказательства

- Два интерпретатора времени: Python scene_at (`video.py:871`) и JS when (`scene.js:129`). Для отсутствующей метки Python возвращает None и пропускает звук, JS использует 0 и запускает изображение. check_scene только предупреждает (`video.py:494`), поэтому рассинхронизация не предотвращается.
- Две реализации форматирования счётчиков: `video.html:1295` и `scene.js:180`; два разметчика rich/headline плюс безопасный accText (`scene.js:12`, `video.html:466`, `video.html:529`). Реальное дублирование контрактов, не доказанный повод механически слить поведение: поддерживаемые форматы различаются.
- Справочники SC_TYPES/SC_IN/SC_FX/SC_TEX/SC_FRAMES вручную повторяют JS/CSS (`video.py:441`). check_scene не проверяет start, фоновые текстуры, уникальность id и полноту структуры; дубли id перезаписываются в `scene.js:111`.
- CSS содержит прежние `.pl` и `.flash` (`video.html:415`, `video.html:431`), а builder chronicle создаёт `.sc/.mc` (`video.html:809`, `video.html:811`). В пяти файлах штатный builder `.pl/.flash` не создаёт; считать их глобально мёртвыми нельзя: JSON разрешает произвольный cls (`scene.js:47`), другие сценарии не проверялись. Автоматическое удаление не рекомендовано.
