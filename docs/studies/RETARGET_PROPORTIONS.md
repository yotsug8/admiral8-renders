# Retarget: проверка разных длин костей

Одна проба на Blender 5.2.0 LTS, build `fbe6228777e7`: у получателя
`spine2` и `head` удлинены на 20%, с 0,20 до 0,24 м. Имена, локальные
оси и порядок цепи не меняются. Остальные четыре кости остаются по 0,20 м;
головы дочерних костей смещены к новым хвостам родителей, соединения сохранены.
Результат: Copy Rotation переносит ориентации, сохраняет собственные длины
получателя и допускает bake с последующим открытием без addon.

## Входы и метод

Используется прежняя [изолированная проба Retarget](RETARGET_SMOKE.md):
`study_retarget_smoke.py` переиспользуется без правок. Точный ZIP Retarget
5.2.0 — 225631 байт, SHA256
`521ec8ff5c2373893ea8022b3f71d27ed191fb73f3a5634cac31585e0dcb7af3`.
Проверка ZIP и побайтовое сравнение распакованных исходников повторяются
до и после запуска. Пакет не устанавливается и не меняется.

Донор восстановлен тем же рецептом предыдущей пробы: шесть костей по 0,20 м,
имена `donor_` + `root → spine1 → spine2 → spine3 → neck1 → head`,
single OBJECT slot, 60 кадров при 30 fps, spine2 вокруг X ±4° и neck1
вокруг Z ±3°. Его траектория дополнительно сравнена с записанными live
матрицами предыдущего smoke и совпала в прежнем допуске.
Исходные rest-данные и хеш ключей донора проверены до/после binding и bake.
Addon штатно добавляет донору вспомогательные `_RET` кости; исходные шесть
костей и action не изменились. Файлы предыдущего smoke не перезаписываются.

Mapping, параметры Copy Rotation и адаптер Python `invoke()` прежние.
Настройки берутся из предыдущего `smoke.json`; создаются ровно шесть
Copy Rotation у получателя. Location/scale/fit-height/apply rotation,
IK-конверсия, matching трансформаций и автоудаление выключены.
Проверяется исходный API `bone_utils.bake_anim()`, не UI оператора.
Известные ограничения фонового invoke и unregister остаются из smoke.

Проверки разделены:

- **Донор → live получателя:** только угловая точность является требованием;
  различие мировых положений записывается отдельно и ожидается ненулевым.
- **Rest получателя:** полное равенство матриц, head/tail, длин, родительских
  связей и connect-флагов до binding, после него, после bake и после reopen.
- **Собственные длины:** длины вычисленных мировых head/tail сравниваются
  с rest получателя, дополнительно измеряется разрыв соседних суставов.
- **Live → baked → reopened:** полные мировые матрицы получателя,
  237 моментов с шагом 1/4 кадра, по 1422 матрицы на сравнение;
  допуск 0,1 мм и 0,05°. После bake все шесть ограничений выключены.
- **Reopen:** отдельный процесс `--factory-startup --disable-autoexec`,
  без импорта/регистрации addon. Один OBJECT slot у baked action.

## Результаты единственной пробы

| Измерение | Максимум |
|---|---:|
| Угловая разница донор → live | 0,000021° |
| Разница положений донор → live | 40,00006 мм |
| Live → baked, положение | 0,000128 мм |
| Live → reopened, положение | 0,000128 мм |
| Live → baked/reopened, угол | 0,000018° |
| Ошибка собственной длины live | 0,000096 мм |
| Ошибка собственной длины baked/reopened | 0,000108 мм |
| Разрыв соединённых суставов | 0 мм |

Rest получателя сохранился точно на всех этапах. Отношение длин
`spine2` и `head` к первоначальным — 1,19999979 / 1,19999976;
отличие от 1,2 обусловлено представлением float32. Остальные отношения — 1.
Донорские исходные rest/action неизменны, пакет побайтово прежний.
Build и reopen завершились с кодом 0, исключений нет. Исправления harness
или повторные варианты этой пробы не потребовались.

Разница в 40 мм измерена между origins костей; удлинение самой head меняет
её хвост, поэтому отдельно проверены длины head/tail. Совпадение origins
донора и получателя здесь было бы неверным критерием успешного retarget.

## Повторение

Нужны проверенный ZIP/распаковка и два исходных результата предыдущего
smoke в `_game/study/retarget_smoke/`: `smoke.json` (binding options) и
`live_matrices.json` (свидетель прежней траектории). Их можно взять из
`artifacts/study_retarget_smoke/` либо получить предыдущей пробой.
Установить те же четыре `BLENDER_USER_*` в `retarget_smoke/profile/`
по инструкции RETARGET_SMOKE. Затем отдельные процессы:

```powershell
& $env:BLENDER --background --factory-startup --disable-autoexec --python-exit-code 2 -P tools/blender/study_retarget_proportions.py -- --root _game/study/retarget_smoke --journal _game/worker_task.json --mode build
if ($LASTEXITCODE -ne 0) { throw 'Stop at the observed compatibility limit' }
& $env:BLENDER --background --factory-startup --disable-autoexec --python-exit-code 2 -P tools/blender/study_retarget_proportions.py -- --root _game/study/retarget_smoke --journal _game/worker_task.json --mode reopen
```

Новые локальные результаты — `retarget_smoke/proportions/`:
`build.json`, `reopen.json`, `receiver_rest.json`, `live_matrices.json`,
`baked.blend`. Передача — `artifacts/study_retarget_proportions/` в ветке
`codex/study-retarget-proportions-artifacts`. ZIP/presets в git не включены.

Подтверждена ограниченная практическая польза при разных длинах и одинаковых
осях/rest-ориентациях. Кожа, оружие, контакт с землёй, разные rest-ориентации,
root motion, изменение масштаба объектов, IK и естественность движения
здесь не проверены. Новых моделей, установок и рендера нет; общий check,
main и общие файлы не менялись. Результат предназначен для сопоставления
с независимой проверкой Пуджа на основном компьютере.
