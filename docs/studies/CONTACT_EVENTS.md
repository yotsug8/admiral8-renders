# Парные события контактов

`tools/blender/study_contact_events.py` переносит расчёт из локального
`lively_fix/audio_events.py`. Зависимости: Blender 5.2, подготовленная сцена
с анимированным корнем актёра и камерами, отчёты `gait_metrics.py` для каждого
непрерывного плана. Игровые модели и JSON остаются внешними локальными ресурсами.
Дополнительные Python-пакеты не нужны.

Из корня репозитория в PowerShell (`BLENDER` — путь к исполняемому файлу):

```powershell
& $env:BLENDER -b _game/skits/chase_v2/lively_fix/scene.blend --python-exit-code 1 `
  -P tools/blender/study_contact_events.py -- `
  --gait _game/skits/chase_v2/lively_fix/gait_side.json `
  --gait _game/skits/chase_v2/lively_fix/gait_front.json `
  --actor-root hoodwink_root `
  --out _game/study/contact_events_portable/foot_events.json
```

Каждый `--gait` содержит `actor`, положительный `fps`, диапазон `frames`
и `paws.{hand_L,hand_R,ankle_L,ankle_R}.contact_entry_times_s`. Времена —
конечные неотрицательные числа, строго возрастающие внутри массива и лежащие
в диапазоне плана. Пустые массивы допустимы. Планы передаются по порядку,
без пересечения диапазонов; актёр общий, fps совпадает с `fps / fps_base` сцены
(абсолютный допуск 1e-9). Секунды абсолютные: кадр = время × fps, без смещения
на `frame_start`. При исходных 30 fps это прежняя формула.

Алгоритм сохранён: для каждого левого касания выбирается ближайшее ещё
неиспользованное правое в пределах 0,05 с включительно; при равенстве — первое
правое по индексу. Время пары — среднее, одиночные касания пропускаются.
Кисти и лодыжки, а также разные планы обрабатываются раздельно. События
стабильно сортируются по времени. `who` берётся из `actor` входного отчёта.

На субкадре события используется активная камера сцены, включая переключения
маркерами. `pan = clamp(2 × projected_x − 1, −0.8, 0.8)`;
`gain = 0.55 × clamp(8 / distance, 0.4, 1)`, расстояние — в единицах сцены.
Формулы, схема JSON и метод исходника сохранены. Скрипт не рендерит, не сохраняет
сцену и не меняет художественный звук; расчёт выполняется на CPU. В JSON
записываются только имена исходных файлов, без абсолютных путей и системных метаданных.

Проверка на `lively_fix/scene.blend`, `gait_side.json`, `gait_front.json`
в Blender 5.2.3: 30/30 событий совпали с `lively_fix/foot_events.json`.
Порядок, `who`, `foot`, `method`, `sources` совпадают точно; максимальные
абсолютные ошибки `at`, `gain`, `pan` равны нулю. Критерии сравнения:
`at ≤ 1e-9 с`, `gain ≤ 1e-6`, `pan ≤ 1e-6`, без относительного допуска.
Локальные результаты: `_game/study/contact_events_portable/` —
`foot_events.json`, `blender.log`, `comparison.json`, `validation.json`.
Отдельные проверки покрывают некорректные времена/диапазоны/fps, пропущенные
поля, однократное использование правого контакта, границу окна и равные расстояния.

Ограничения: входные контакты считаются предоставленными измерениями выбранной
поверхности; высота костей не используется, геометрия опоры заново не проверяется.
Соответствие отчёта текущей геометрии, его SHA256 и соответствие выбранного корня
полю `actor` обязан обеспечить вызывающий код. Скрипт не подтверждает физическую
опору, отсутствие скольжения, видимость лап или качество звука. Проекция корня
не проверяет окклюзию и положение за камерой; ограничение pan сохранено даже
для корня вне кадра. Масштаб сцены влияет на gain, как и в исходнике.
